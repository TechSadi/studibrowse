# Deploying StudiBrowse

This guide takes StudiBrowse from nothing to production, and is also how to redeploy it from scratch. No secret is ever stored in the repo. Every value below is set in a dashboard, and the tables at the end list each one.

## How production fits together

```
REST:      browser ──https──▶ Vercel (static app + rewrite /api/*) ──https──▶ Render proxy ──▶ Express ──▶ MongoDB Atlas
Socket.IO: browser ──wss────────────────────────────────────────────▶ Render proxy ──▶ Socket.IO
Errors:    browser ──https──▶ Sentry (studibrowse-web)          server ──https──▶ Sentry (studibrowse-api)
```

- **Web: Vercel.** It serves the built app from `apps/web`, falls back to `index.html` for every route, and sends the security headers. All of that is in `apps/web/vercel.json`.
  - REST stays on the page's origin. `/api/*` is rewritten to Render, so the refresh cookie is first-party.
- **API: Render.** One web service runs Express and Socket.IO, set up in `render.yaml`.
  - The socket connects straight to Render (`VITE_API_URL`), because Vercel can't proxy WebSockets.
- **Database: MongoDB Atlas.**
- **Errors: Sentry**, one project for the API and one for the web app. Logs are JSON lines in Render's log view.
- **Deploys: GitHub Actions** (`.github/workflows/deploy.yml`). It runs only after the CI workflow passes on a push to `main`.
  - It deploys the API first, waits until `/api/health` reports the new commit, then builds and deploys the web app.
  - Neither Vercel nor Render deploys on its own: Render has `autoDeployTrigger: off`, and Vercel has `git.deploymentEnabled: false`.
- **`TRUST_PROXY=2`:** a REST request passes through two proxies (Vercel, then Render's), so Express takes the visitor's IP from the second-to-last `X-Forwarded-For` hop. Per-IP rate limits depend on this. See `docs/decisions/security.md`.

## Before you start

You need accounts on GitHub (with the repo), MongoDB Atlas, Render, Vercel and Sentry. You also need the services the app already uses:
- **Google Cloud:** an OAuth client for Google sign-in.
- **Resend:** a verified sending domain.
- **Cloudinary:** for room file uploads.

Pick a region and use it everywhere. This guide uses **Frankfurt** (Render `frankfurt`, Atlas AWS `eu-central-1`). To use another one, change `region` in `render.yaml` too.

## 1. MongoDB Atlas

1. **Create a cluster:** Create > **M0 (free)**, provider AWS, region `eu-central-1` (Frankfurt), name `studibrowse`.
2. **Add a database user:** Database Access > Add New Database User.
   - Username `studibrowse-api`, a long autogenerated password.
   - Built-in role: none. Specific privileges: **`readWrite` on database `studibrowse`**. The API needs nothing else.
3. **Allow Render's addresses:** Network Access > Add IP Address.
   - The safest choice is Render's outbound IP ranges for the service. They're in the Render dashboard, under the service > **Connect** > **Outbound**, and the service only exists after step 3. Add each range listed there.
   - Until then, or if you accept the risk, you can add `0.0.0.0/0`. Then only the database password protects the cluster, so keep it long and random.
4. **Copy the connection string:** Database > Connect > Drivers. It looks like this:
   ```
   mongodb+srv://studibrowse-api:<password>@studibrowse.xxxxx.mongodb.net/studibrowse?retryWrites=true&w=majority&appName=studibrowse
   ```
   - Put **`/studibrowse`** (the database name) after the host. Without it, Mongoose writes to `test`.
   - URL-encode any special characters in the password.
   - This is `MONGODB_URI`.

Indexes, including the TTL indexes that expire refresh and reset tokens, are created by Mongoose when the API first starts.

## 2. Sentry

1. Create two projects:
   - **`studibrowse-api`**, platform Node.js (Express).
   - **`studibrowse-web`**, platform React.
2. **Get each project's DSN:** Settings > Projects > (project) > Client Keys (DSN).
   - The API's DSN is `SENTRY_DSN` (in Render).
   - The web project's DSN is `VITE_SENTRY_DSN` (in Vercel).
   - DSNs aren't secrets; they only allow sending events.
3. **Create a token for source maps:** Settings > Developer Settings > **Organization Tokens** > Create. It gets the `project:releases` and `org:read` scopes it needs. This token is `SENTRY_AUTH_TOKEN`, and it **is a secret**.
4. **Note your organization slug** (Settings > General). This is `SENTRY_ORG`.

Without a DSN, the API logs a warning at boot and the web app sends nothing. Everything else still works.

## 3. Vercel project (for its domain)

You need the web app's domain before Render can be configured, so create the Vercel project first.

1. Add New > Project > import the GitHub repo.
2. Configure the project:
   - **Root Directory:** `apps/web`. Keep "Include files outside the root directory" on, because the app imports `packages/shared`.
   - **Framework Preset:** Vite. Build command `vite build` and output directory `dist` (the defaults).
   - **Node.js version:** 22.x (Settings > Build and Deployment, after creation).
3. Deploy. This first deploy may not work yet; that's fine.
4. Note the production domain, e.g. `https://studibrowse.vercel.app`. This is `CLIENT_ORIGIN`.

To use a custom domain, add it in Settings > Domains and use it as `CLIENT_ORIGIN` instead.

## 4. Render (the API)

1. **Create the service from the Blueprint:** Render dashboard > New > **Blueprint** > connect the GitHub repo. Render reads `render.yaml` and proposes one web service, `studibrowse-api`.
2. Render asks for every variable marked `sync: false`. Fill them in (the table in "Render environment" below explains each one):
   - `MONGODB_URI`
   - `CLIENT_ORIGIN`: the Vercel domain from step 3, with `https://` and no trailing slash.
   - `GOOGLE_CLIENT_ID`
   - `RESEND_API_KEY`, `EMAIL_FROM`
   - `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`
   - `SENTRY_DSN`

   `JWT_ACCESS_SECRET` is generated by Render, and the fixed values (`NODE_ENV`, `TRUST_PROXY`, ...) come from the file.
3. Apply. The first deploy runs. When it's live, open `https://<service>.onrender.com/api/health`. It should show `{"ok":true,"db":"up",...}`.
   - If it says `db: down` (status 503), check the Atlas IP access list and `MONGODB_URI`.
   - If the service exits at boot, the log names each missing or invalid variable.
4. **Note the service URL**, e.g. `https://studibrowse-api.onrender.com`. Render adds a suffix if the name is taken. This URL is the API origin.
5. **Copy the deploy hook:** Service > Settings > **Deploy Hook** > copy. This is `RENDER_DEPLOY_HOOK_URL`, and it is a secret: anyone with it can trigger deploys.
6. If you skipped it in step 1, add Render's outbound IP ranges (Connect > Outbound) to Atlas and remove `0.0.0.0/0`.

**What the Free plan means:**
- The instance sleeps after 15 minutes without traffic. The next visitor waits about a minute while it wakes.
- Live presence (who's in which room) is held in memory, so it's lost when the instance sleeps or restarts. People's tabs reconnect and rejoin on their own.
- Running timers are stored in MongoDB and picked up again at boot.
- For an always-on instance, change `plan: free` to `plan: starter` in `render.yaml`, or change the plan in the dashboard.

## 5. Point the web app at the API

`vercel.json` can't read environment variables, so the API origin is written into it in **three places**:
- the `/api/:path*` rewrite destination;
- `https://<api origin>` in `connect-src`;
- `wss://<api origin>` in `connect-src`.

If your Render URL isn't `https://studibrowse-api.onrender.com`, replace it in `apps/web/vercel.json` and merge the change into `main`. `apps/web/src/lib/deployConfig.test.ts` fails if the three disagree.

## 6. Vercel environment

In the Vercel project, open Settings > Environment Variables. Add each variable for the **Production** environment:

| Name | Value |
| --- | --- |
| `VITE_API_URL` | The Render origin, e.g. `https://studibrowse-api.onrender.com` (no trailing slash) |
| `GOOGLE_CLIENT_ID` | The same OAuth client id as on Render (the build passes it to the browser) |
| `VITE_SENTRY_DSN` | The `studibrowse-web` DSN |
| `SENTRY_AUTH_TOKEN` | The Sentry organization token (mark it **Sensitive**) |
| `SENTRY_ORG` | Your Sentry organization slug |
| `SENTRY_PROJECT` | `studibrowse-web` |

Then get the ids that GitHub Actions needs:
- **`VERCEL_PROJECT_ID`:** Project > Settings > General > Project ID.
- **`VERCEL_ORG_ID`:** your team's id (Team Settings > General > Team ID), or for a personal account, Account Settings > General > Vercel ID.
- You can also run `npx vercel link` in the repo root. It writes both ids to `.vercel/project.json`, which is gitignored.
- **`VERCEL_TOKEN`:** Account Settings > Tokens > Create, scoped to that team. It's a secret.

## 7. Google sign-in

In Google Cloud Console, open APIs & Services > Credentials > your OAuth client. Under **Authorized JavaScript origins**, add the Vercel domain, e.g. `https://studibrowse.vercel.app`. Google Identity Services needs no redirect URI.

## 8. Resend and Cloudinary

- **Resend:** verify your sending domain (Domains > Add). `EMAIL_FROM` must use it, e.g. `StudiBrowse <noreply@yourdomain.com>`. Create an API key with sending access: this is `RESEND_API_KEY`.
- **Cloudinary:** get the cloud name, API key and secret from Settings > API Keys. Under Settings > Security, turn on **"Allow delivery of PDF and ZIP files"**, or shared PDFs won't open.

## 9. GitHub

1. **Create the environment:** repo Settings > Environments > New environment > **`production`**. Optionally limit deployments to the `main` branch, under "Deployment branches and tags".
2. In that environment, add these **secrets**:

   | Secret | From |
   | --- | --- |
   | `RENDER_DEPLOY_HOOK_URL` | Render > service > Settings > Deploy Hook |
   | `VERCEL_TOKEN` | Vercel > Account Settings > Tokens |
   | `VERCEL_ORG_ID` | Step 6 |
   | `VERCEL_PROJECT_ID` | Step 6 |

3. And this **variable**:

   | Variable | Value |
   | --- | --- |
   | `API_ORIGIN` | The Render origin, e.g. `https://studibrowse-api.onrender.com` |

## 10. First deploy

Merge into `main`, or push a commit to it. Then:

1. **CI** runs: lint, typecheck, tests, coverage and build.
2. If CI passed, **Deploy** starts (Actions > Deploy):
   - `api` triggers the Render deploy hook, then polls `API_ORIGIN/api/health` until `release` is this commit (up to 15 minutes).
   - `web` checks out the same commit and runs `vercel pull`, `vercel build --prod` (which uploads source maps to Sentry and deletes them from the output), and `vercel deploy --prebuilt --prod`.

If CI fails, or a newer push cancels it, nothing deploys.

## 11. Check the deploy

Work through this list after the first deploy, and after any change to infrastructure or variables:

- [ ] `https://<api>/api/health` answers 200 with `"db":"up"` and `"release"` matching the commit.
- [ ] Open the Vercel domain. Sign up, log in, then reload: you're still logged in, which means the refresh cookie works through the rewrite.
- [ ] Log in with Google.
- [ ] Open a room in two browsers. Check the participant list, chat and the timer all stay in step, and you're seeing the socket over `wss://` to Render.
- [ ] Upload a PDF and an image to a room, then open both.
- [ ] Request a password reset and check the email arrives, with a link pointing at the Vercel domain.
- [ ] The browser console shows no CSP violations on login, Home, a room, a profile and Settings.
- [ ] **Per-IP rate limits see real visitors.** Run this twice from your computer:
  ```
  curl -si -X POST https://<vercel domain>/api/auth/login -H 'Content-Type: application/json' -d '{}' | grep -i '^ratelimit:'
  ```
  The remaining count (`r=`) drops by one each time. Then run it once from a different network (e.g. a phone hotspot): it should start again from the top. If both networks share one count, `TRUST_PROXY` is too low.
- [ ] **Sentry receives errors.**
  - API: the boot log must *not* contain `SENTRY_DSN is not set`. Without that warning, Sentry started. The API has no endpoint that fails on purpose, so the first real event is the first unexpected 500, socket INTERNAL_ERROR or background failure. To see one now, run the API locally with the same `SENTRY_DSN` and `NODE_ENV=production` against a stopped MongoDB, then sign up. The failed database call ends up in Sentry.
  - Web: in the browser console, run `setTimeout(() => { throw new Error('sentry web test') })`. The event should show readable source lines (source maps) and the commit as its release.
- [ ] Render > Logs shows JSON lines with `"service":"studibrowse-api"`, a text `level` and `release`.

## Rolling back

- **API:** Render > service > Events/Deploys > pick an earlier deploy > **Rollback**.
- **Web:** Vercel > Deployments > pick an earlier production deployment > **Instant Rollback** (or Promote).
- Then fix forward on `main`. The next passing push deploys normally.
- Database changes aren't rolled back. The schema has no migrations; Mongoose only adds indexes.

## Rotating secrets

| Secret | How | Effect |
| --- | --- | --- |
| `JWT_ACCESS_SECRET` | Render > Environment > edit (generate with `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`) > save, which redeploys | Access tokens expire at once. Tabs refresh with their refresh cookie, so nobody is logged out |
| Atlas password | Atlas > Database Access > Edit password, then update `MONGODB_URI` on Render | The API is down between the two steps; do them together |
| `RENDER_DEPLOY_HOOK_URL` | Render > Settings > Deploy Hook > Regenerate, then update the GitHub secret | None |
| `VERCEL_TOKEN` | Vercel > Tokens: create a new one, update GitHub, delete the old one | None |
| `SENTRY_AUTH_TOKEN` | Sentry > Organization Tokens: create a new one, update Vercel, revoke the old one | None |
| Resend, Cloudinary and Google keys | Create a new key in the service, update Render (and Vercel for Google), revoke the old key | None |

## Every environment variable

### Render (API service)

| Variable | Required | Secret | Value |
| --- | --- | --- | --- |
| `NODE_ENV` | yes | no | `production` (set by `render.yaml`) |
| `TRUST_PROXY` | yes | no | `2` (set by `render.yaml`) |
| `LOG_LEVEL` | no | no | `info` (set by `render.yaml`) |
| `JWT_ACCESS_SECRET` | yes | **yes** | Generated by Render (`generateValue`). At least 32 characters; the `.env.example` value is refused |
| `MONGODB_URI` | yes | **yes** | Atlas connection string with `/studibrowse` |
| `CLIENT_ORIGIN` | yes | no | `https://<vercel domain>`. Must be https; CORS, Socket.IO and reset links use it |
| `GOOGLE_CLIENT_ID` | yes | no | OAuth client id (`…apps.googleusercontent.com`) |
| `RESEND_API_KEY` | yes | **yes** | Resend API key |
| `EMAIL_FROM` | yes | no | `StudiBrowse <noreply@your-verified-domain>` |
| `CLOUDINARY_CLOUD_NAME` | yes | no | Cloudinary cloud name |
| `CLOUDINARY_API_KEY` | yes | no | Cloudinary API key |
| `CLOUDINARY_API_SECRET` | yes | **yes** | Cloudinary API secret |
| `SENTRY_DSN` | no (warns) | no | `studibrowse-api` DSN |
| `SENTRY_RELEASE` | no | no | Leave unset: it defaults to `RENDER_GIT_COMMIT`, which Render sets |
| `ACCESS_TOKEN_TTL_SECONDS`, `REFRESH_TOKEN_TTL_DAYS`, `BCRYPT_COST` | no | no | Defaults 900, 30 and 12 |
| `PORT` | no | no | Set by Render; don't override it |
| `HUSKY`, `MONGOMS_DISABLE_POSTINSTALL`, `COREPACK_ENABLE_DOWNLOAD_PROMPT` | build only | no | `0`, `1`, `0` (set by `render.yaml`). They skip git hooks, the test-database download, and corepack's prompt |

### Vercel (web project, Production)

| Variable | Required | Secret | Value |
| --- | --- | --- | --- |
| `VITE_API_URL` | yes | no | Render origin, used only for the socket |
| `GOOGLE_CLIENT_ID` (or `VITE_GOOGLE_CLIENT_ID`) | yes | no | OAuth client id |
| `VITE_SENTRY_DSN` | no | no | `studibrowse-web` DSN |
| `SENTRY_AUTH_TOKEN` | no (no source maps without it) | **yes** | Sentry organization token. Never prefix it with `VITE_` |
| `SENTRY_ORG` | with the token | no | Sentry organization slug |
| `SENTRY_PROJECT` | with the token | no | `studibrowse-web` |

`SENTRY_RELEASE` is set by the deploy workflow to the commit. It isn't set in Vercel.

### GitHub (environment `production`)

| Name | Kind | Value |
| --- | --- | --- |
| `RENDER_DEPLOY_HOOK_URL` | secret | Render deploy hook URL |
| `VERCEL_TOKEN` | secret | Vercel access token |
| `VERCEL_ORG_ID` | secret | Vercel team or account id |
| `VERCEL_PROJECT_ID` | secret | Vercel project id |
| `API_ORIGIN` | variable | Render origin |

### Outside the three dashboards

| Where | What |
| --- | --- |
| Atlas > Network Access | Render's outbound IP ranges (or `0.0.0.0/0`) |
| Google Cloud > OAuth client | The Vercel domain as an Authorized JavaScript origin |
| Cloudinary > Security | Allow delivery of PDF and ZIP files |
| Resend > Domains | The domain used in `EMAIL_FROM`, verified |
| `apps/web/vercel.json` | The Render origin, in 3 places (step 5) |
